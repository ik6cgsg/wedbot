# Схема БД

Проект использует SQLite-базу `res/wed.db`. Схема создаётся автоматически через Exposed при старте приложения.
Основная сущность системы — пользователь (`users`), а данные опроса по еде вынесены в отдельные таблицы `food_infos`
и `food_info_drinks`.

### Общая модель

- Один пользователь может иметь 0 или 1 запись с предпочтениями по еде и напиткам.
- Одна запись food_infos может иметь несколько напитков через таблицу связи food_info_drinks.
- Таким образом, связь выглядит как users → food_infos → food_info_drinks.

## Таблица users

Хранит гостей, администраторов и их текущие статусы по опросам.

| Поле            | Тип          | Null   | Ограничения         | Описание                                                   |
|-----------------|--------------|--------|---------------------|------------------------------------------------------------|
| id              | INTEGER      | нет    | PK, AUTOINCREMENT   | Внутренний идентификатор пользователя                      |
| chat_id         | LONG         | да     | UNIQUE              | Telegram chat id, появляется после первого успешного входа |
| username        | VARCHAR(255) | да     | UNIQUE              | Telegram username пользователя                             |
| name            | VARCHAR(255) | да     |                     | Имя гостя                                                  |
| phone           | VARCHAR(30)  | да     | UNIQUE              | Телефон для сопоставления с гостем                         |
| alias           | VARCHAR(255) | да     |                     | Псевдоним / короткое имя                                   |
| sex             | ENUM         | нет    | default NE_BYLO     | Пол пользователя                                           |
| event_status    | ENUM         | нет    | default THINKING    | Статус участия в мероприятии                               |
| villa_status    | ENUM         | нет    | default THINKING    | Статус проживания в коттедже                               |
| transfer_status | ENUM         | нет    | default THINKING    | Статус по трансферу                                        |
| role            | ENUM         | нет    | default GUEST       | Роль пользователя                                          |
| food_info_id    | INTEGER      | да     | FK -> food_infos.id | Ссылка на ответы по еде и напиткам                         |

Значения enum-полей

- sex: MALE, FEMALE, NE_BYLO
- event_status: APPROVED, SLEEVE, THINKING
- villa_status: APPROVED, SLEEVE, THINKING
- transfer_status: THINKING, NEED, SELF_HANDLE, SOCIAL_LEGEND
- role: ADMIN, STAFF, GUEST

Назначение таблицы

- хранение профиля гостя;
- сопоставление Telegram-пользователя с записью в списке гостей;
- хранение результатов опросов;
- фильтрация по ролям для админских действий и рассылок.

## Таблица food_infos

Хранит результат опроса по горячему блюду и текстовый комментарий.

| Поле       | Тип     | Null | Ограничения       | Описание                                      |
|------------|---------|------|-------------------|-----------------------------------------------|
| id         | INTEGER | нет  | PK, AUTOINCREMENT | Идентификатор записи опроса                   |
| additional | TEXT    | нет  |                   | Комментарий: аллергии, пожелания, ограничения |
| menu       | ENUM    | нет  | default HROOHROO  | Выбранное основное блюдо                      |

Значения menu: HROOHROO, REEBOK, VEGI.

## Таблица food_info_drinks

Таблица связи для списка выбранных напитков.

| Поле         | Тип     | Null | Ограничения                                | Описание                      |
|--------------|---------|------|--------------------------------------------|-------------------------------|
| food_info_id | INTEGER | нет  | PK, FK -> food_infos.id, ON DELETE CASCADE | Ссылка на запись в food_infos |
| drink        | ENUM    | нет  | PK                                         | Один выбранный напиток        |

Составной первичный ключ = food_info_id + drink

Значения drink: WHITE, RED, SHAMPOO, WHISKEY, VODKA, ALCOHOLESS

## Особенности и ограничения

- chat_id, username и phone уникальны, но nullable (ожидается при этом, что то-то из этого обязано быть).
- Пользователь может существовать в БД до первого входа: тогда chat_id ещё NULL.
- Наличие food_info_id в users означает, что опрос по еде уже был заполнен.
- При удалении записи из food_infos связанные напитки из food_info_drinks удаляются каскадно.
- Таблицы создаются автоматически на старте через SchemaUtils.create(...).
